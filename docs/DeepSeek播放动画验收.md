# DeepSeek 播放动画验收

> 历史记录说明：下方 2026-10-15 的数字属于当时的 TTS＋RVC 版本。当前版本为纯 TTS；新版本复验范围见文末，不将旧结果冒充本次验收。

验收日期：2026-10-15。对象为本机 DeepSeek Harness 的真实聊天栏按钮、Agent Voice 服务及当前 TTS＋RVC 声音链路。未调整模型、参考音频或声音参数。

## 已验证结果

| 场景 | 结果 |
| --- | --- |
| 服务未开启 | 显示“服务未启动”，波形静止 |
| 点击开启服务、查看状态 | 真实服务启动，显示当前声音、自动朗读开关和队列数量 |
| 生成语音 | 显示“生成中”，波形静止 |
| 实际播放 | 聊天栏及菜单波形运动，状态为“播放中” |
| 播放完成 | 恢复“待播放”，波形静止 |
| 播放队列中途停止 | 队列归零，未播放任务取消，恢复静止 |
| 声音方案 | 读取 5 个已保存方案，重新应用当前方案成功，声音配置哈希不变 |
| 自动朗读开关 | 从聊天栏分别开启、关闭，核对本机配置均生效 |
| 关闭服务 | 真实服务退出，显示“服务未启动”，无残留动画 |

真实朗读正文以“工作好久啦，起来动一动、喝口水吧～”开头，TTS＋RVC 任务完成，音频时长 12.04 秒。停止测试使用两个播放任务，结果为一个完成、一个取消，队列为零。测试结束恢复原先的服务运行状态和 Harness 开关，并核对声音配置哈希一致。

## 回归检查

- Python 全套 93 项通过，覆盖服务、队列、取消、MCP、模型包和连接器等。
- Node 连接器、聊天栏控制和嘴型桥接测试通过；新增覆盖只读通道、状态脱敏、播放阶段、轮询不重叠、停止后丢弃旧响应、隐藏暂停、断线与卸载清理。
- 原生界面自检通过：17 页、120 次页面切换、523 个控件，错误为零。
- 本机前后端及 desktop／headless profile 的按钮文件同步；修复了独立 RPC 路径在桌面载体返回 HTTP 405 的问题，实际使用共享 `/api` 路由验证通过。

## 使用边界

波形表示播放阶段，不表示音量、口型或每个字的时序。播放中轮询间隔为 650 毫秒，空闲为 3 秒，状态变化可能稍有延迟；非常短的音频可能在两次检查之间完成。启用系统“减少动态效果”后只显示阶段文字。此次未修改 AIRI 或 Codex 界面；其已有协议与桥接测试通过不等同于对所有外部版本重新做实机验收。

## TTS 引擎切换后的复验

分别保存 CosyVoice、GPT v5 Turbo、ProPlus 声音方案，通过同一 MCP 切换并生成新任务；确认引擎与版本匹配，停止后队列清空，DeepSeek 动画随实际播放启停。连接器与音频 API 不因引擎改变。注意此项是复验步骤，不等于每次更新已重新运行外部模型会话。详见《[TTS 使用手册](../TTS使用手册.md)》。
