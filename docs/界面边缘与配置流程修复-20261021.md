# 界面边缘与配置流程修复 · 2026-10-21

## 用户报告与复现

用户截图中的侧栏白色矩形/透明边界已在 WIP 的自定义背景下复现。声音方案列表在同一机器 DPI 下两行文字挤压；旧行高 40 像素，回归测出的最低需要为 73 像素。首次配置素材依赖白底 WebP 反色混合，动画主要旋转图片；AIRI 使用整张旧配置截图作为旁边插图。下载入口缺失，使“选引擎”和“导入引擎包”变成必须重复操作的感觉。

## 实现

- `AnimeButton` 圆角外侧绘制最近的不透明容器，而不是穿过黑色侧栏去画整窗照片。默认与明亮背景使用像素回归，修改前均失败，修改后通过。照片统一加可读性遮罩，仍保留用户选择的全窗背景。
- 方案列表使用 DPI 行高和实际字体高度计算两行位置；扩大列表、去除多余边框，并下移方案维护区，保留滚动。绘制不再使用固定 19/16 像素行框。
- 使用原作者原生透明 PNG；透明度、来源、许可、SHA-256 已核验。内置 imagegen 两次抠图均有残边，结果未采用、未加入项目；没有用脚本进行像素编辑。
- 原图不再旋转。各页使用与配置含义对应的扫描、文字到声音路径、文件投递、依赖节点、声纹与消息交接。真实任务期间才循环，暂停、减少动画、离页销毁继续有效。
- AIRI 恢复原网页的页面内黑白曲面舞台、宋体标题、粉色图标、线条声浪；直接使用原图标和实际开关/按钮，不把配置截图放在旁边。
- 流程为“选择引擎 → 在线准备源码和模型 → 检查运行依赖”。本地引擎包和已安装路径放入备用折叠入口，下载失败自动展开；用户可随时主动选本地，不强迫先下载失败。依赖页缺源码/模型时提示返回，不重复下载引擎。
- 结合视频中的使用分工，增加本地备用途径折叠、抽屉进入过渡、抽屉内字段错误、真实阶段反馈和轻提示；破坏性方案操作保留撤销入口。

视觉约束：石墨黑 `#101116`、冰白 `#F3F5F8`、电紫 `#B49AFF`、AIRI 粉 `#E8B6CE`。文字优先，字体服从系统 DPI；侧栏使用稳定容器底色，图片只负责辅助。AIRI 的白色舞台是实际页面构图，其余页不通过给图片增加黑框融入背景。
