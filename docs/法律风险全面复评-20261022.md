评估日期：2026-10-22。主要法域：中国大陆；另考虑 GitHub 托管、第三方开源许可和 Windows 二进制分发。评估人：Codex 辅助审查，使用 `legal-risk-assessment` 与 `compliance-check`。本报告不是律师法律意见、行政许可或权利人授权，不产生律师保密特权。

## 1. 结论与当前事实

**可继续以合法材料开展本地开发和测试，但当前材料不足以支持“全部组件已获公开再分发授权”“任意商用”或“已经完成法律合规验收”的结论。** 不需要因为软件具有 TTS 功能就一概停止开发；应按具体功能、实际材料、分发对象和运营方式决定处理措施。

最需要处理的是以下五组问题：

1. **项目自己的许可没有确定。** 根目录没有 LICENSE；第三方 MIT／Apache 文本不授权 Agent Voice 自己的代码。没有 LICENSE 不是作者开发违法，但与希望他人自由二次开发的目标冲突。
2. **实际模块包有许可缺口。** CosyVoice 包漏带 Matcha-TTS 根 MIT 声明；FFmpeg 的对应源码和再分发材料未形成闭环；环境还含 GPL／LGPL 依赖，不能仅凭 CosyVoice Apache、GPT MIT 就判断整体许可。
3. **模型与声音的权利链仍应分开。** 基础权重、编码器、词典、参考录音、台词、表演、可识别自然人的声音不是同一种授权。把导入导出拆成模块、取消默认声音都不能替代这些授权。
4. **隐私、生成内容标识与运营边界尚未完整验收。** 数据主要在本机是有利因素，但默认 Codex 自动朗读、任务正文留存、AIRI 令牌复制、模块执行权限仍要清楚告知和控制。公开在线服务需要单独审查，不能把本地测试结果直接外推。
5. **GitHub 默认分支与当前代码不同。** 实时认证查询确认仓库现在是 **private**，默认 `main` 为 `e142e74`；本轮最新代码在开发分支，领先 main 52 次提交。须知、模块拆分等不能当成 main 已具备的能力。私有托管也不等于曾分发的本地压缩包自动收回。

有证据支持的风险降低措施：

- 当前本体 ZIP 没有模型权重和参考人声；只有九个原创合成界面提示音，没有随本体预装音色模块。
- 当前首次配置先展示须知与引擎许可；继续配置前需点击“我已阅读须知”。这只是阅读记录，不是录音权利人的单独授权，也不是完整用户协议。
- 音色包读写实现位于主动安装的可选模块；核心仍可使用用户自备参考录音。
- 主服务绑定 `127.0.0.1`，业务接口要求随机令牌；未认证健康接口仅返回受限状态。MCP 自检不启动 TTS、不以能否发声冒充连接成功。
- 检查本地可达 Git 引用中选定的音频／模型／归档扩展名，共找到 9 个对象，均为界面提示音。**这不是全历史图片、文本秘密、远端附件或已删除不可达对象的清白证明。**

当前分发材料未形成该构建及静态包含库的对应源码、许可、构建信息和有效获取方式闭环。只放 FFmpeg 首页链接不足以证明履行相应再分发义务。应取得可追溯构建或自行制作合规构建，提供实际适用的版权、LGPL／GPL 文本和对应源码等材料。这里的 CLI 子进程调用**不自动意味着整个 C# 桌面程序必须 GPL**；具体结合作用和分发义务应逐项分析。[FFmpeg 官方许可说明](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n4.3.2/LICENSE.md)、[LGPLv3 原文](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n4.3.2/COPYING.LGPLv3)

## 5. 声音、参考录音、训练和可选模块

### 5.1 四条权利链分别建立

| 对象 | 应确认的权利／边界 | 本轮状态 |
|---|---|---|
| 台词、音乐、文章、录音制品、表演 | 复制、训练使用、改编／处理、传播、表演者及录音制作者等相应许可 | 未取得每份素材的完整合同；不是“能下载就能训练” |
| 可识别自然人的声音 | 是否获得覆盖克隆和相应用途的有效同意；用途、期限、地域、撤回与处理方式 | 阅读须知和录音所有权不能替代本人声音授权 |
| 基础模型与训练权重 | 基础模型使用／衍生／再分发限制，新增训练数据授权，权重与参考音频是否允许打包 | 按引擎和模型逐个核对；轻量包不天然免除授权义务 |
| 虚构角色或人工合成声音 | 是否包含可识别演员声音，以及录音、台词、角色形象、商标与合同限制 | 不预设角色本身享有自然人声音权，也不预设机械音完全无权利负担 |

民法典第 1023 条对自然人声音作专门保护衔接；著作权法对作品、表演和录音制品分别规定权利与限制。是否适用例外须结合具体用途判断，私人研究或个人使用不能作为所有声音克隆、训练与传播行为的总豁免。[民法典人格权编](https://www.cac.gov.cn/2020-06/01/c_15925617772683193.htm)、[著作权法](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

2026-09-07 最高法发布的涉 AI 意见进一步明确了可识别自然人合成人声的保护方向，也要求按场景、过错及控制能力区分相关主体责任。其对部分免费开源代码提供者保留了适当免责空间，**不是所有完整应用、模型包、定向训练和分发活动的自动免责条款**；具体事实仍需法律判断。[最高法官方全文，第（三）（四）（十二）（十三）项](https://ipc.court.gov.cn/zh-cn/news/view-6033.html)

### 5.2 当前模块隔离的实际作用

模块拆分减少本体直接提供打包声音的范围，这是有用的工程措施。但本地 TTS 仍可选择参考录音，可选模块也仍能导出参考音频和完整／增量权重。

`optional-modules/voice-packages/backend/tts_bundle.py` 的清单记录引擎、模型指纹、参考路径和声音参数，**没有形成结构化的声音授权证据字段与发布审核结果**；哈希只证明文件一致，不能证明权利人的身份和同意。训练指南已有须知，但训练工具只校验文件、台词等技术条件，不核验授权真实性。

建议建立本地权利记录：素材标识与哈希、来源、权利人／授权主体、允许训练／生成／公开／商用／分发的范围、期限、基础模型许可、证据文件位置、变更与撤回处理。默认不要把合同中的身份证件、签名、联系方式或原始敏感证据装入公开音色包；可公开许可摘要，原件受限保存。是否需要用户单独同意及何种法律基础，应按实际处理活动判断。

旧音色已经不随本次本体分发，**不应擅自删除用户本机资产**。若以后提供任何音色、Demo 音频或复刻素材，先对那份材料建立单独结论。当前没有为历史人物／角色素材出具清权证明。

| 手工或 Harness 正文 | 本地队列、TTS worker；生成后 `data/output/*.json` 可含正文，旁边保存 WAV | 文本可能是个人信息、客户资料或商业秘密；提供明确范围和删除入口，避免在公共空间自动外放 |
| Codex 自动朗读 | 默认 Codex 开启；服务会轮询最近会话 JSONL，选取可见 assistant commentary／最终回复，跳过识别出的子代理 | 默认启用不是非法结论，但首次告知应说明会读取哪些会话及内容；建议提供按会话／项目限制及明确暂停入口 |
| 参考音频、台词与训练产物 | 用户选定位置、声音方案、训练清单／token／报告及可选包 | 声纹／敏感内容应结合识别能力与风险评估，不把所有 WAV 机械归类，也不忽视可识别声纹 |
| 生成缓存清理 | 默认 30 分钟策略、保留最近 3 条；每 900 秒检查；清理 WAV 时删除同名 JSON | 最近 3 条可长期留存，正在使用的文件受保护；清理不等于清空日志、参考、训练数据、备份与导出包 |
| 连接令牌 | 随机令牌在本机设置；MCP 运行时读取；AIRI 桥接把连接信息写入目标运行内容 | 不把 settings、修改后的 app.asar、连接截图直接分享；明确卸载／撤销／轮换令牌时的联动更新方法 |
| 外部下载 | 引擎、模型、pip／NLTK 等请求外站 | 下载服务可获连接信息；与上传参考录音给云端推理不同。引擎换为外部 API 时需重新告知和评估 |
| 日志／诊断 | 应用日志有容量轮转，诊断含设备／路径；上游 worker 日志仍可能含正文 | 容量限制不等于按时间删除；对故障分享做脱敏预览与最小化，明确不能上传的材料 |

个人信息保护法要求结合处理角色、目的和合法基础开展告知、最小必要与安全保护；敏感个人信息规则、必要时的单独同意和影响评估不能被一次阅读勾选替代。自然人个人／家庭事务适用例外有边界，不能扩大为开发者经营或公开服务的豁免；下载公开模型本身也不自动构成用户数据出境。[个人信息保护法，第 13、17、19、28—30、38—39、55、72 条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

实际应补充一份与运行行为一致的数据说明：开发者是否接收数据、收什么、不收什么、保存位置、删除范围、第三方连接、投诉与权利请求路径。若开发者不接收用户本地正文，应准确说明，而非虚构云端处理者或强制收集身份证明。

安全控制不是法律清权，但关系到泄漏责任与用户预期。当前有 loopback 与令牌鉴权；CORS 为 `*`，不能据此断言无需令牌也能任意控制或已经被攻击。建议评估受信来源限制、令牌生命周期、AIRI renderer 暴露范围、声音模型加载风险及模块签名。模块安装已有本地代码执行提示；SHA-256 不证明发布者可信。

## 7. AI 标识、公开服务和 AIRI 的监管边界

### 7.1 当前不能声称完成输出标识合规

本次未发现覆盖 WAV／MP3、合并片段及 AIRI／API 输出全过程的合规标识实现。旁置 JSON、文件名、首次配置须知和技术验收成功都不能代替适用场景下的文件内标识。对适用服务，需分别验证交互或音频显式标识、文件内元数据隐式标识以及下载／导出、转码后的保留情况。[标识办法第 2、4、5、10 条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

GB 45438—2025 为现行强制性国家标准，2025-09-01 实施；对属于其适用范围的服务，应以实际条款设计和验收。先做业务适用性判断，再决定本地使用与公开输出的产品模式，不能一概把所有本机朗读定性为违规，也不能把本机播放验收当成公开服务合规证明。[国家标准官方状态](https://std.samr.gov.cn/gb/search/gbDetailed?id=301E0388CB75788DE06397BE0A0AE1B4)、[TC260 标准文本](https://www.tc260.org.cn/upload/2025-03-15/1742009439794081593.pdf)

### 7.2 不自动把开发者、用户、托管平台混为同一角色

生成式 AI 暂行办法第 2 条、深度合成规定第 2 条等均有适用范围；后者也对相关技术支持活动作规定。需要确认开发者是否只提供通用本地工具、是否实际控制生成服务、是否托管模型／用户数据、是否向境内公众持续提供服务、是否提供特定编辑模型与运营支持。适用时再分析安全评估、算法备案、内容治理等具体义务，不能仅以用户数量或“有 API”判断。[生成式 AI 暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)、[深度合成管理规定](https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm)

AIRI 本地播放桥接与经营情感陪伴产品也应区分。2026-07-15 起实施的拟人化互动规则针对面向境内公众的持续情感互动服务，明确排除了不涉及持续情感互动的工作助手等。将来若经营虚拟伴侣、持续情感陪伴或面向未成年人服务，应另行评估，不能沿用当前工作助手定位。[2026 年正式办法第 2 条及相关服务要求](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)

## 8. 素材、第三方集成、宣传与权利反馈

**UI 素材。** 当前已留存部分 3dicons CC0 来源与 AIRI MIT 文本，原创提示音有可复现生成脚本，主图有 AI 生成记录，这些是有利证据。它们不覆盖仓库全部 PNG／SVG、设计截图、后续新增图标及字体。应建立“文件—来源—许可版本—修改—用途”逐项清单；不能把参考过抖音视频、发布会或 PPT 理解为取得素材复制许可。当前主要使用系统字体；若未来打包字体文件，应单列许可。AI 生成图的服务条款、近似标识与潜在第三方权利也需按实际情况审查，生成记录不保证排他版权。

**AIRI／Harness。** AIRI 上游 MIT 允许符合条件的修改与分发代码，但不等于其所有依赖、商标和用户账户都获得相同许可。当前桥接会修改用户原 `app.asar` 并备份；应继续明确告知、支持恢复、提醒更新可能失效，不分发包含用户登录状态的已修改安装目录。AIRI 图标用于兼容性说明，不表示上游背书。[AIRI 官方许可](https://raw.githubusercontent.com/moeru-ai/airi/main/LICENSE)

DeepSeek 使用本地连接／聊天栏扩展，Codex 采用 MCP 与本地会话读取。没有证据表明需要绕过付费或身份验证，也没有据此确认全部宿主条款已经审查；后续发布应记录宿主实际版本、允许的扩展方式和恢复方案，避免宣传“宿主官方认证”。Codex 当前聊天客户端未重载的问题属于验收边界，不能用独立探针通过冒充实际客户端全部加载。

**宣传与使用承诺。** “所有电脑都能用”“零延迟”“100% 还原”“任意商用”“生成成功率长期≥95%”等应有对应范围与可复现证据；有限硬件样本的成功率不等于所有用户的保证。商业宣传受反不正当竞争、广告及消费者权益规则约束。软件免责声明不能当然排除法定责任。[2025 年修订反不正当竞争法第 9 条](https://www.csrc.gov.cn/beijing/c105536/c7582544/content.shtml)

**投诉和通知。** 当前未见专门、完整的权利投诉处理规则。应由维护者选择真实可用的接收渠道，可采用仓库私密安全报告或专用联系渠道；不要在公开 Issue 索要身份证、完整声音合同或私密录音。收到可信侵权通知时，应登记材料、核实并对相关版本／素材采取与事实相称的措施，保存必要记录，及时回复。不能在没有调查事实的情况下宣称所有代码、所有用户都必须下线。

## 9. 风险优先级与整改次序

采用 Skill 的“影响 1—5 × 发生可能性 1—5”框架：1—4 低、5—9 中、10—15 高、16—25 严重。数字是**针对登记场景的工作优先级判断，不是诉讼概率、罚款预测或对已违法的认定**。未授权音色、公开在线服务等条目的评分以未来触发对应场景为前提；当前私有仓库不等于已经触发。详细依据、责任角色、剩余风险和关闭证据见登记册。
