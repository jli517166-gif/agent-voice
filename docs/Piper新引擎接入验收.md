# Piper 新引擎接入验收

日期：2026-10-15。位置：`E:\App\Agent 测试`。按用户要求实际下载新的 TTS 引擎，验证可扩展性；本次使用 Piper，而不是系统 SAPI。

## 下载与安装

- 引擎：`piper-tts==1.8.0`，来自 [Piper 官方项目](https://github.com/OHF-Voice/piper1-gpl)对应的 PyPI 发布。
- 模型：[zh_CN-huayan-medium](https://huggingface.co/rhasspy/piper-voices/tree/main/zh/zh_CN/huayan/medium)，含 63,201,294 字节的 ONNX、配套 JSON 和模型卡。模型 SHA-256 与 Hugging Face 公布的 LFS 对象一致。
- 目录：`tts-engines/piper`；独立虚拟环境、模型和依赖清单，安装后约 268.7 MiB。虚拟环境复用现有主 Python 的基础库，未往 CosyVoice 环境安装 Piper 依赖。
- 模型和运行环境留在本机，不提交 GitHub，也未加入原公共发布包。

## 实际验证

| 场景 | 结果 |
| --- | --- |
| 首页选择新引擎 | `piper` 可选，显示专用 ONNX 模型设置，隐藏 CosyVoice 参考条件 |
| 打开模型选择 | 初始目录直接进入 `tts-engines/piper/models`，选中真实下载的 ONNX 成功 |
| 桌面“生成并播放” | Piper＋RVC 任务完成，输出 48000 Hz 音频并播放 |
| Piper 直出 | 生成并播放完成，输出 22050 Hz、约 3.20 秒音频 |
| 语速调整 | 语速 1.3 的音频约 2.79 秒，短于语速 1 的约 3.20 秒 |
| 长文分句 | 生成并按原顺序播放完成，首段生成约 515 毫秒 |
| 中途停止与清队列 | 正在播放和排队的两个任务均取消，队列归零，状态恢复静止 |
| 停止后再次调用 | MCP 朗读正常完成，没有串入已取消任务的响应 |
| 错误模型 | 缺少模型或无效配套 JSON 会报错，当前声音保留 |
| 保存声音方案 | 桌面保存“Piper 中文 · huayan 直出”，独立文件夹内容与保存值一致 |
| 跨引擎切回 | 桌面切回原 CosyVoice，原声音字段一致，实际朗读完成 |
| 再次应用 Piper 方案 | 引擎、独立模型路径、语速、参考条件及开关与保存值一致 |
| 重启语音服务 | Piper 方案保留，中文长句再次生成播放完成 |
| 真实 stdio MCP | 8 个工具正常，识别当前 Piper 方案、应用方案和列出方案均正常，备用 RVC 参数保留 |

测试结束恢复原声音、原 Harness 开关和服务运行状态，原有方案均保留；额外保留一个 Piper 声音方案，供用户切换。没有训练或调整已有 CosyVoice 权重及声音参数。

## 修复和回归

- 修复 Windows 中文安装路径导致 Piper 发音库寻找构建机路径并退出的问题；采用短路径或英文临时发音数据缓存，不改第三方库。
- 模型路径、默认模型和 Python 路径独立保存，不借用 CosyVoice 配置。无关参考录音不会阻止 Piper 应用。
- 修复本地方案被备用 RVC 参数影响、MCP 无法正确识别当前方案的问题；MCP 应用本地方案也保持备用 RVC 参数。
- 非 CosyVoice 引擎下禁用 CosyVoice 音色包导出，保留导入以切回 CosyVoice，避免错误标注引擎。
- Python 全套 101 项通过；随后新增的方案匹配回归包含在 MCP 8 项测试中通过。Node 连接器、聊天栏和嘴型桥接测试通过。
- 原生 UI 自检：17 页、120 次切换、542 个控件，错误为零；额外检查 Piper 控件隔离、模型路径保留和方案字段恢复。

## 范围

Piper 使用这个 ONNX 模型的既有声音，本次不提供参考音频克隆或 Piper 训练界面。CosyVoice 四种音色包仍只针对 CosyVoice，Piper 参数通过声音方案保存。其他未适配 TTS 仍需新增适配，不能仅修改目录名称。

延迟数据为本机单次观察，不代表其他电脑的性能。中文模型用于功能测试，不以音色相似度验收。CosyVoice 切回后的冷加载加播放约 45.44 秒；本次没有改变其推理链路。
