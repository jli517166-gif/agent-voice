# Codex 语言控制验收

本版采用原生“语音控制”技能和 MCP，不再提供 Codex 自定义浮窗、面板或聊天栏按钮。DeepSeek 原有聊天栏按钮保留。

## 内置朗读核查

检查了官方插件扩展、语音文档，以及本机 Codex CLI 的 `app-server generate-json-schema --experimental` 输出。公开协议包含实时语音启动、音色列表和追加可朗读文本；实时音色为固定枚举。未发现内置朗读播放源替换、本机 TTS 提供方注册或内置播放控件接管接口。因此，本版没有接管内置朗读，也不将实时语音接口当作接入成功。

此结论只针对已核查的公开接口，不断言所有客户端内部实现均不可能修改。后续只有出现可验证接口时再接入。

参考：[官方插件扩展](https://developers.openai.com/plugins/build/extensions)、[官方语音功能](https://learn.chatgpt.com/docs/features/voice)。本机协议输出保留于忽略目录 `acceptance/codex-native-read-aloud-schema`，不随软件打包。

## 移除和验证

- 移除窗口跟随代码、浮窗及其设置／托盘入口、MCP Apps 面板、HTML 资源及 UI 元数据；旧本机文件归档至 `data/retired-codex-ui`，不再加载。
- 语言命令保留服务状态、启停服务、停止并清空队列、列出与切换声音、开关自动朗读及朗读指定正文。
- MCP 单元与真实 stdio 协议检查 7 项通过，覆盖正文准确提交、停止、声音方案和当前 Harness 的开关隔离。
- 原生 UI 17 个页面、120 次切换通过；DeepSeek 聊天栏控制回归通过。
- 本机新建真实 stdio MCP 连接确认版本为 1.4.0，只暴露 8 个语言控制工具；启动后状态为运行中，停止命令成功，列出 5 个声音方案。声音配置哈希一致，测试结束恢复原先服务关闭状态。
- 接入验证以工具返回的真实状态为准；朗读入队不等于播放完成。模型和声音参数未调整。

## TTS 引擎切换后的复验

分别保存 CosyVoice、GPT v5 Turbo、ProPlus 声音方案，通过同一 MCP 切换并生成新任务；确认引擎与版本匹配，停止后队列清空，DeepSeek 动画随实际播放启停。连接器与音频 API 不因引擎改变。注意此项是复验步骤，不等于每次更新已重新运行外部模型会话。详见《[TTS 使用手册](../TTS使用手册.md)》。
