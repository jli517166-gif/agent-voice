# 功能模块拆分与验收

2026-10-22：用户要求取消默认音色，将音色包导入导出从软件本体完整移出。当前实现区分本体、引擎、环境、功能扩展；保存声音方案和手动选择模型／参考录音继续属于本体。

## 实现位置

| 层 | 位置 | 职责 |
|---|---|---|
| 本体 UI | `ui/FeatureModulesPage.cs` | 通用导入、列表、完整性检查、打开和移除模块，不包含音色包界面 |
| 原生安装 | `ui/ModulePackages.cs` | `.avmodule` 校验、受限目录、SHA-256、事务安装、回滚及移除；不要求 Python |
| 本体模型 | `service/model_integrity.py`、`file_integrity.py`、`voice_profiles.py` | 本地模型完整性、固定参考录音和声音方案；不导入归档实现 |
| 音色包窗口 | `optional-modules/voice-packages/ModuleWindow.cs` | 独立程序，四种 CosyVoice／两种 GPT 导出、导入、命名、文件库与结果反馈 |
| 音色包后端 | 该模块的 `backend/` | 全部音色归档读写和兼容校验；旧配置归档兼容代码也在可选目录内 |
| 本体构建 | 根 `build.ps1` | 只编译 `ui/`，不复制可选实现，排除旧默认清单与旧归档脚本 |
| 模块构建 | 可选模块自己的 `build.ps1` | 独立编译并生成 `.avmodule`；不打入本体、不携带音色资产 |

原 `ui/ConfigurationPage.cs` 已移除；`service/`、`tools/` 中不再有 `tts_bundle.py`、`config_bundle.py`。旧 `--bundletest` 不再是本体命令。首次配置桥接不认识 `import-voice`，没有音色包文件选择器；原“声音”页仅保留手动参考录音和自己的已保存方案。这里不是用开关隐藏仍然存在的归档实现。

新安装既不读取也不校验旧默认清单来注入声音。即使有人复制旧 `assets/bundled-voice.json`，本体和 Python 也只创建无音色的初始配置。已有用户配置优先保留，不以改版为由删除用户录音或模型。

## 用户流程

1. 未安装模块：控制台、TTS、声音方案、训练及连接照常可用，没有音色包业务入口。
2. 选择“模块 → 导入模块”，选可信 `.avmodule`，核对来源并安装；安装后才出现该模块的“打开模块”按钮。
3. 打开独立窗口，使用主程序已经应用的当前声音；导出按模式说明选择，导入自动匹配引擎和版本。
4. 空闲语音服务会在文件操作期间暂时关闭，结束后尝试恢复；有任务时拒绝操作。恢复失败明确提示，不冒充声音就绪。
5. 移除后活动 `modules/<id>` 目录不再存在、列表不再发现或启动该模块。只把模块代码移入恢复备份，用户模型、参考录音和保存方案不删除。

“保存声音方案”仍保存本机当前设置及固定参考，和制作跨电脑归档是不同操作。自己的训练模型默认放 `trained-voices/`；模块自己的归档库为 `voice-model-packages/`。旧用户目录保留，允许继续手动选取。

## 通用模块接口 v1

包为 ZIP 格式，后缀 `.avmodule`，只有 `manifest.json` 和 `payload/<相对路径>`。清单示例：

```json
{
  "format": "agent-voice-module", "version": 1, "kind": "feature",
  "platform": "windows-x64", "id": "example", "name": "示例功能",
  "moduleVersion": "1.0.0", "apiVersion": 1,
  "entrypoint": "modules/example/module.exe",
  "components": ["modules/example"], "defaults": {},
  "files": [{"path": "modules/example/module.exe", "size": 123, "sha256": "文件的64位小写SHA-256"}]
}
```

模块 ID 使用小写字母开头，可有数字和短横线，最长 64 字符；接口版本不匹配拒绝。文件只写自身 `modules/<id>`，不能用清单改写声音、账号、引擎路径和控制密钥；不允许夹带 WAV、模型权重或目录链接。单模块解压总量最多 128 MiB。入口由宿主传入 `--root <软件目录>`，不通过命令行传 token。窗口关闭后宿主重新读取当前设置。

安装器生成 `module.json` 记录已安装清单。打开前核对清单内文件长度和 SHA-256；缺失、损坏或不兼容的模块不能启动。SHA-256 是完整性校验，不能认证作者；模块是完整权限的本地代码，用户必须确认来源可信。

独立模块可以借用本体稳定接口，但本体不能反向导入该模块。音色包窗口通过主程序程序集读取配置和请求本机服务，自己的 Python CLI 借用核心状态与模型校验；核心服务不会搜索模块目录，也不按名字自动加载音色包脚本。

## 发布和法律边界

本体 ZIP 排除已安装的 `modules/`、用户声音、状态和默认清单，并再次过滤旧归档脚本。功能模块分开提供，用户必须主动装载，不能由首次配置静默安装。

取消默认声音降低了发行者直接附带录音和角色模型的风险；拆成模块不等于免除录音、人物声音、训练数据、模型及第三方依赖的授权义务，也不更改已分发旧包的权利状态。不要宣传“装模块就可以任意克隆或公开传播”。项目自身许可证和完整依赖许可清单仍待所有者确认。
