# Agent Voice 法律风险整改方案（待审核）

日期：2026-10-22。依据：[法律风险全面复评](法律风险全面复评-20261022.md)及 [15 项风险登记](legal-audit/20261022/risks.json)。本文件是供项目所有者审核的方案；尚未修改程序行为、确定项目许可证、重打包或公开仓库。法律适用及复杂组合分发仍需专业复核。

## 建议采用的产品范围

继续做“让 Harness 通过用户自选的本地 TTS 发声”的桌面软件，保留 CosyVoice、GPT-SoVITS、MCP、AIRI、自定义参考录音、训练指导及可选模块。首次公开交付聚焦本机运行，不把它同时做成由开发者经营的公网生成或情感陪伴平台。后者将来有需求再单独确定合规方案。

继续分开交付软件本体、TTS 引擎、环境、功能模块。本体及官方模块不附带用户声音、参考录音、训练角色权重、个人背景或账户。用户可在本机使用自己有权使用的材料；技术功能保留，不把“只能用自己的声音”当成对合法授权材料的额外限制。

开发者分发某个引擎或依赖时，该组件的许可义务仍存在。拆模块、让用户下载或写免责声明，都不是统一免责办法。对许可暂不明确的资源，暂缓由项目打包分发，不因此删除用户已有文件或取消其他已经明确授权的模块。

## 第一阶段：先完成发行许可和材料清单

这一阶段主要改变文档、构建与发行检查，优先避免触及已满意的声音效果。

| 工作 | 具体做法 | 完成标准 | 对应风险 |
|---|---|---|---|
| 自有代码许可 | 建议自有代码用 MIT；先确认权利主体和贡献来源，由所有者确定。第三方代码、图标、模型另列，不能统称都由本项目 MIT 授权 | 根 LICENSE、版权主体、README 和模块许可说明一致 | L01 |
| 完整物料清单 | 按本体、每个引擎、每个环境和模块登记名称、版本／修订、来源、哈希、许可证、声明文件、修改记录与分发结论；纳入 DLL、词典、子模型，不止 pip 元数据 | 实际包的文件能够映射到物料记录，未知项明确保留 | L02—L05 |
| 缺失版权声明 | 补 Matcha-TTS 根 MIT 文本，逐项补上其他裁剪复制组件所需声明 | 打出来的对应包确实包含正确版本文本，不只源码目录中有文件 | L02 |
| FFmpeg 与 GPL／LGPL | 优先采用可追溯、能取得匹配源码及构建信息的 FFmpeg。核查 praat-parselmouth、Distance、frozendict、soxr 及原生库的实际许可、用途和组合方式；无用项经回归再移除，必要项履行义务或使用经核查的替代 | 相应二进制、许可、源码与获取方式闭环，必要专业复核完成 | L03—L04 |
| 模型与专有组件 | 分别核对 GPT 两版本、HuBERT、RoBERTa、G2PW、声纹／声码器、fastText、NLTK、CUDA、.NET 和 WebView2；不把主引擎许可套给所有文件 | 每项来源与分发范围有证据；不明确的相关包不进入“已审核”发行列表 | L05 |
| 素材来源 | 登记图标、图片、音效、字体及公开截图。已有 CC0、AIRI MIT、原创提示音记录继续使用；其余逐项核查，来源不明的公开素材替换或取得授权 | 每个实际发布素材有可追溯记录，公开截图无私人内容 | L10 |

**许可证建议不是替你作决定。** MIT 适合希望别人较自由地使用、修改及商业化二次开发的目标，但要求保留相应声明；Apache-2.0 还包含明确专利许可等安排。若你希望禁止商业使用，则应另行设计相应许可，不能在 MIT 上附加禁止商用条件后仍声称是标准 MIT 开源。[MIT 说明](https://choosealicense.com/licenses/mit/)、[Apache-2.0 原文](https://www.apache.org/licenses/LICENSE-2.0)

补齐许可文字本身通常不影响音色。裁减或替换依赖可能影响发音、速度和训练，应记录当前模型及生成参数，先验证真实调用关系，再对三个引擎进行短文、长文、数字／中英文、语速、切换和实际播放回归。不得为了减少依赖而直接卸掉发音链需要的组件。

建议新增的工程材料为组件许可清单、`THIRD_PARTY_NOTICES`、完整 SBOM 与来源记录；四类包各自带适用的许可材料。对于需要提供对应源码的组件，按许可允许的实际交付方式提供匹配源码及必要构建材料，可作为同版本下载附件，不要求用户安装源码才能运行。不能只放一个上游首页或一个无效“源码索取”提示。

## 第二阶段：保留声音功能，补上权利记录

| 位置 | 建议改变 | 使用体验与边界 |
|---|---|---|
| 参考音频／训练入口 | 简短说明应有权使用材料，提供“记录素材来源与用途”入口；明确录音、台词、表演、可识别自然人声音与模型许可分别确认 | 不反复弹窗，不强制上传身份证、合同或录音给开发者 |
| 声音方案 | 可以附本地权利说明：素材标识、来源、用途、许可期限及证明文件位置 | 自定义声音参数仍正常保存；来源说明不是软件认证 |
| 可选音色包模块 | 新导出包增加许可摘要及基础模型来源；明确包内包含哪些录音／权重。旧包可导入，缺少说明显示“授权信息未记录”，不能显示“已获授权” | 不以缺少机器可读字段就自动判定用户侵权；不擅自替旧包补虚假授权 |
| 项目官方发行流程 | 只发布已经核对授权范围的 Demo、声音或材料；本轮继续不附带默认声音 | 不因用户勾选声明就把其材料加入官方推荐或发行包 |

权利记录建议区分：训练、生成、个人使用、公开传播、商业用途、参考录音再分发、权重再分发，以及范围、期限和地域。需要取得自然人同意的场景，由真实权利人作出有效同意，不能由导入者的一次勾选代替。[最高法关于声音及相关主体责任的意见](https://ipc.court.gov.cn/zh-cn/news/view-6033.html)

合同原件、身份、签名、联系方式等证明可受限保存在本机或其他安全位置，默认不进入公开音色包。公开包最多包含适合公开的许可摘要及证据引用。实际授权真实性不能由哈希、MCP 自检或软件自动确认。对应风险 L06。

## 第三阶段：让用户清楚控制读取、外放和留存

建议新安装时仍默认选择 Codex 作为宿主，但将“自动读取会话并朗读”做成单独明确选择，首次关闭，用户在配置中开启；手工朗读和用户明确发起的 MCP 朗读正常保留。既有用户的自动朗读设置不静默改变，升级时清楚告知其范围。这一默认值变化需要所有者审核。

| 工作 | 建议实现 | 验收重点 |
|---|---|---|
| 自动朗读范围 | 显示将读取哪些宿主与可见回复；逐步支持当前会话／指定项目范围和一键暂停 | 没启用的不监控；不能开启一个项目就无提示读取其他项目；启停状态可信 |
| 数据说明 | 单独的本地数据说明，列正文、音频、设置、日志、训练、AIRI、外部下载与外部 API 的流向 | 文案与代码一致，不泛称“永不联网”，不虚构开发者已经收集了本地正文 |
| 正文与音频保留 | 设置中给保留期限和关闭后清理等选择；默认避免无限保留最近几条；给用户保留所需内容的自由 | 停止、失败、中断、重播和程序重启后的删除范围明确，清理不破坏正在使用文件 |
| 清理入口 | 区分生成音频／正文、日志、连接记录、备份；训练素材、模型与导出包另行选择并说明 | 一键清理不等于删除用户模型；每项说明是否包含正文和备份 |
| 故障报告 | 默认脱敏，导出前预览；不自动附令牌、录音或完整台词 | 实际导出文件检查，不只测试界面有提示 |
| 令牌与 AIRI | 可撤销连接或轮换本地令牌，更新相关桥接配置并重新验证 | 旧连接失效，宿主接入提示明确，不误删 AIRI 登录状态 |
| 模块与模型信任 | 保留代码执行提醒，列来源及实际权限；官方包使用独立可信发布信息／签名方案，安装失败能回退 | 哈希不冒充发布者认证；不把可执行模块称为完全隔离的安全数据文件 |

这些是降低风险的工程建议，具体告知、合法基础、单独同意和其他法定义务仍按实际处理角色判断，不给每个纯本地用户强制加身份认证。对应 L08、L12、L13。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 第四阶段：把生成内容标识做进输出链路

建议将“本机朗读”和“准备对外分享”在交互上清楚区分。公开输出采用更明确的标识与导出检查；但这个产品分类不是法律豁免开关，不能让用户点“本地”就跳过对其实际适用的要求。

- 播放界面可清楚显示“AI 合成语音”，先用界面提示帮助识别，不在每句本地朗读前强行插入提示声，避免直接破坏现有听感。
- 按适用标准实现音频文件内的隐式标识，并确认隐私字段最小化；不把合同、个人姓名、令牌或本地绝对路径写进去。
- 对属于适用服务的文件下载／导出，在文件中保留满足要求的显式标识；交互界面提示不能自动替代离开界面后的文件要求。
- WAV、MP3、长文分片合并、重采样、API 返回、AIRI 实际投递分别验收。标准规定的字段与方式按正式文本实现，不拿旁置 JSON 或自己发明的字段宣称完全达标。
- 不提供以规避适用标识义务为目的的“去标识”功能；上游或素材已有的合法标识不应被流水线意外清除。

是否适用网络服务标识义务先按业务事实判断。以上是建议采取的产品措施，不表示当前所有离线播放都必须插入同一种声音水印；也不表示写一个 `AI=true` 即满足标准。对应 L07、L09。[标识办法第 2、4、5、10 条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

## 第五阶段：维护、投诉和发布检查

| 工作 | 具体做法 | 验收标准 | 风险 |
|---|---|---|---|
| 宿主与 AIRI 集成 | 界面明确本地修改和恢复方式，保留上游声明，继续提示更新可能失效；核对实际宿主允许的扩展方式 | 不带账号状态或令牌分发；不宣称得到官方认证；修改与恢复可验证 | L12 |
| 权利／安全反馈 | 由所有者选一个实际可用的私密接收渠道；提供必要措施、核验、回复、复审流程，公开 Issue 不收身份证和完整合同 | 可投递、可定位责任人，能够单独撤回有问题素材／包而不是一律删除整个项目 | L15 |
| 对外宣传 | 仅标注有证据的硬件、版本、样本和条件，区分连接、生成、播放三个结果 | 不把有限测试改写成任意电脑零延迟、任意音色百分百还原或长期固定成功率保证 | L14 |
| 仓库与成品一致 | 先核对默认分支与开发分支差异及主工作区未提交内容；审核后整合或明确正式发布标签，不直接覆盖 main | 下载入口、源码标签、说明书、包内版本及实际 SHA 一致 | L11 |
| 历史与素材 | 检查所有待公开分支、图片和附件；旧说明注明历史，敏感问题按实际证据处理 | 不把 `.gitignore` 当成历史清理，不未经确认强推或重写历史 | L10—L11 |
| 发布自动检查 | 从“文件名与哈希盘点”升级到“实际文件映射＋许可材料检查＋人工决定记录” | 未完成项列出具体组件、理由和解决入口；不能由用户勾选绕过项目自己的公开发布检查 | L01—L05、L11 |

建议检查只阻止相应**发行产物被标记为可公开发布**，不要因为一个附属模型许可待核查，就让已合法安装的软件无法本机运行。即使自动检查全绿，也只是项目工程门槛通过，不是权利人授权、律师意见或政府许可。

## 实施顺序与交付件

| 顺序 | 交付件 | 何时进入下一步 |
|---|---|---|
| A：文档和许可 | 代码许可决定、逐组件清单、必要声明、素材来源、发行范围和未知项列表 | 确认要发布的每个包；外部授权问题不设虚假完成时间 |
| B：构建与依赖 | 下载保留许可、必要源码及构建材料、干净环境、包级检查报告 | 相关引擎／环境的运行回归和再分发证据完成 |
| C：程序体验 | 权利说明、自动朗读范围、数据保留／清理、令牌／模块保护、输出标识 | 空白安装及已有配置升级均验收，声音链路回归通过 |
| D：正式发布 | 对应源码标签、四类独立包、许可材料、手册、投诉渠道、发布验收记录 | 所有适用的发布条件满足后再由所有者决定发布；不直接沿用旧包 |

具体权重和组件的授权，可能取决于上游材料或权利人的回复，不能承诺用几天代码修改就全部解决。我的工程工作可以补记录、实现控制与验证；许可证选择、真实授权和业务法律适用不能伪造或由软件自动替代。

## 请所有者审核的三个产品决定

1. 自有代码建议 **MIT**；这允许别人商业使用和二次开发，不代表所有声音与第三方依赖都适用 MIT。实际版权主体还需明确。
2. **新安装的自动朗读默认关闭，配置时主动开启**；Codex 仍为默认宿主选择，已有设置保留。
3. **首个公开版定位本地桌面工具，不同时经营公网生成／情感陪伴服务**；所有声音、训练及模块自定义能力在相应合法范围内保留。

上述是建议而非已经应用的改动。本方案获确认后，再依次实施；有具体投诉、公众服务或复杂组合许可争议时，按实际情况请中国法律专业人员复核。预期效果是降低并持续控制风险，不承诺“零法律风险”。
