# 发布许可检查

自有代码采用根 `LICENSE` 的 MIT；不将第三方引擎、二进制、权重和素材统一改为 MIT。查看根 `THIRD_PARTY_NOTICES.md` 和 `docs/legal-components.json`；“声明已确认”只代表相应文本／来源记录，不等于整包完成法律审查。

构建保留许可；引擎准备保留 LICENSE、NOTICE、COPYING 和模型卡。CosyVoice 引擎包遇到已裁剪 Matcha 源码时，会附上记录的 Matcha 根 MIT 文本，不改用户源码。下载分片、请求头、字节码与运行日志不进入新包。

四类打包 CLI 均生成同名 `.compliance.json`。里面包含归档及逐文件 SHA-256、大小、具体未完成项和许可审查状态。默认本地候选包可以生成，不代表公开分发许可通过。公开发行检查使用：

```powershell
python tools/release_compliance.py --package <候选包路径> --report <报告路径> --review <审查记录.json> --public
```

`tools/module_packages.py` 也支持 `--review` 和 `--public`。失败退出码为 2；留下的文件仍是未审核候选包，不能据此上传公开 Release。报告不参与自身归档哈希，审查绑定的是最终归档字节。改一个文件、重新压缩或换包都必须重新核对。

审查记录格式：

```json
{
  "artifactSha256": "最终归档的SHA256",
  "files": {
    "包内准确路径": {
      "sha256": "该文件的SHA256",
      "decision": "redistribution-reviewed",
      "license": "实际适用的许可",
      "source": "锁定版本的来源",
      "evidence": "具体许可、源码交付和其他必要证据的位置",
      "reviewer": "实际负责审查的人或机构",
      "reviewedAt": "实际审查日期"
    }
  }
}
```

不能批量填虚假许可或把 `NOASSERTION` 当作许可通过。逐文件登记应关联到实际组件；文件清单不是完整的依赖关系 SBOM。待补的 Python 库／原生 DLL 关系、模型来源、对应源码及许可证义务仍在清单中，不能以自动检查代替权利人授权或专业法律判断。

重点未完成项包括：旧 FFmpeg 精确构建的对应源码与静态依赖材料，GPL／LGPL 库的组合分发义务，GPT 各权重／附属模型的许可，CUDA／Microsoft 实际版本条款以及未逐项溯源的素材。没有证据前，不把相应引擎／环境／本体包标成可公开分发；用户自己的合法本机安装不因此被禁用。本次没有把旧大包重新标成“审核通过”。

音频输出：WAV 使用 AIGC 数据块，MP3 使用 ID3 TXXX 的 AIGC；字段按 TC260-PG-202510A 布局。`AgentVoice.local` 仅为本地软件标识，不冒充登记的公众服务提供者编码。分享导出在原音频前加入“以下音频由人工智能合成。”，不重新生成正文；普通本机朗读不在每句前插提示。以上不构成对所有线上服务场景的合规保证。

官方依据：[生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[音频文件元数据实践指南 TC260-PG-202510A](https://www.tc260.org.cn/tc260/sjzn/202508/5afb978a1a294937bf66fd96ccdd0f6a/files/bb1fb60134144c0e98554a15a03f0098.pdf)（来源：全国网络安全标准化技术委员会秘书处）。

## 官方构建来源证明

`.github/workflows/candidate-provenance.yml` 提供独立、仅手动运行的 GitHub / Sigstore 来源证明流程，绑定准确 EXE 哈希、源仓库、工作流与修订，不持有长期私钥。它不创建公开 Release，也不使许可待核查的组件通过发行检查。当前本机构建没有该远端签名，不得把普通 SHA-256 描述成发布者认证。

维护者运行该工作流并成功取得证明后，可按准确文件验证：

```powershell
gh attestation verify "agent语音.exe" -R jli517166-gif/agent-voice --signer-workflow jli517166-gif/agent-voice/.github/workflows/candidate-provenance.yml
```

仓库必须是预期所有者与仓库，不能相信任意压缩包自己附带的“可信仓库”。离线核验需另保存证明与信任根，不能离线请求失败后显示成功。GitHub 公有仓库和私有仓库的计划支持不同；私有仓库需支持该功能的 Enterprise Cloud 计划。本项目目前不自动更改仓库可见性，未运行、权限不足或失败时不声称已签名。此来源证明也不是 Windows Authenticode 代码签名，不会消除 Windows 安全提示。

方案依据：[GitHub 官方证明文档](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)、[官方 actions/attest](https://github.com/actions/attest)。

正式发布应核对源码标签、GitHub 默认下载入口、包内文档、模块／引擎版本、SHA-256 与回归报告。不覆盖有未提交修改的主工作区，不强推改写历史。历史包的内容和许可结论不会因本次新增文档自动改变。
