# 架构与开发

## 运行链路

```text
桌面控制台 / Harness / AIRI
             |
     本地 API 与 MCP 控制
             |
     文本处理和任务队列
             |
        当前 TTS 适配器
             |
     音频校验与播放 / AIRI 投递
```

UI 和推理进程分离。配置决定当前引擎、完整模型、参考条件与输出；提交的任务保留配置快照。切换模型会释放旧工作进程，语速等运行参数不应无故重载模型。

## 核心文件

| 文件 | 职责 |
|---|---|
| `ui/Program.cs` | 应用启动、实例隔离与配置入口 |
| `ui/Models.cs` | 桌面配置模型 |
| `service/state.py` | 配置迁移、字段校验与资源路径 |
| `service/server.py` | 本地 HTTP API、鉴权和任务入口 |
| `service/jobs.py` | 排队、分段、取消、清理和投递 |
| `service/pipeline.py` | 引擎生命周期、生成和音频校验 |
| `service/engine_registry.py` | 引擎能力和适配器加载 |
| `service/voice_profiles.py` | 声音方案与参考资源完整性 |
| `integrations/agent_voice_mcp.py` | MCP 工具协议 |
| `tools/environment_repair.py` | 环境检查与补齐 |

## 使用说明与输出

首次配置只负责资源和连接，不包含强制阅读步骤。须知、TTS 许可和使用范围集中在设置中。音频输出策略由 service/audio_policy.py 管理：生成和导出不插入分享口播，已有的音频容器标识保留；这不等同于素材授权或法律认证。

## 约束

- 服务应核对令牌、根目录和实例身份，避免端口串接。
- 停止必须使旧任务失效，不让过期工作重新播放。
- 写入配置和安装组件应采用临时文件、校验和可恢复提交。
- 文件清理仅处理应用拥有的生成物，不沿目录链接越界。
- 安装完成、模型就绪、播放完成和宿主已连接分开表示。
- 私人数据与测试产物不进入源码仓库。

开发与验证步骤见 [贡献指南](../CONTRIBUTING.md)。
