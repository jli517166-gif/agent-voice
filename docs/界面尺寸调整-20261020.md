# 界面尺寸与排版调整 · 2026-10-20

用户反馈上一版部分控件、文字过小，大小比例奇怪。本轮只调整桌面工作台的尺寸、排版与相关回归，不改变语音链路、连接协议或首次配置的视觉方案。

## 原因

上一轮修复避免了最大化时的字体膨胀，但仍把整张页面按窗口高度压缩，最低允许 4.5pt。同时卡片在宽、高两个方向被独立拉伸，字体与巨大按钮不成比例。侧栏使用固定物理像素，在本机 150% 显示缩放下明显偏窄。另一个问题是按物理像素测量的文字高度被作为逻辑坐标再次放大。

## 统一尺寸规则

- 保留石墨黑、冰白、电紫主题；本轮不加入装饰或新动画。
- 页面正文、操作按钮与输入框使用至少 11pt，标题保持 26pt；侧栏辅助信息 10.5pt。
- 侧栏宽 190 个逻辑像素，导航按钮高 44；移除状态区两个空占位行。
- 普通窗口默认客户区 1180×780 逻辑像素，最小外窗 1100×640，并根据当前屏幕工作区限制，避免初始窗口超出屏幕。
- 页面使用等比、受限宽度的内容列；几何缩放范围为设计宽度的 92%–112%，再应用系统 DPI。最大化时内容居中，按钮和卡片不随屏幕无限变宽、变高。
- 缩小时使用滚动查看完整内容，不再把字体压小。较长帮助与训练页允许滚动，但所有控件必须位于可滚动文档内。
- 首页剩余高度用于扩展正文编辑区和队列；常用句与播放操作随之下移，不拉大按钮文字。停止、重播、生成操作统一为 40 个逻辑像素高。
- 自绘 `AnimeButton` 也明确关闭 AutoSize，避免原生 Button 类型检查漏掉它，造成按钮高低不一。
- 文字测量统一换算逻辑坐标；滚动条宽度只预留一次，避免往返最大化后发生位置漂移。

## 验证与交付

测试机 Windows、144 DPI。旧版新增“字体过小 / 导航过窄”断言后，83 场景共 980 条失败；新版窗口回归 83 场景通过，同时保留字体上限、遮挡、还原一致性、自定义背景检查，并增加嵌套控件边界检查。页面超出视口时验证可滚动文档的边界，未删除越界断言。

最终构建为 `build-readable-ready-20261020/agent语音.exe`；构建成功，仍有 `SetupWizard.cs` 原有 CS1998 警告。

本机证据位于：

- `acceptance/readability-ready/window-layout.json`
- `acceptance/readability-ui-ready/ui-results.json`
- `acceptance/readability-welcome-ready/welcome-results.json`
- `acceptance/readability-scroll-ready/scroll-results.json`
- `acceptance/readability-ready/live/`：普通窗口、最大化及重点页面实拍

最终结果：窗口回归 83 项、完整界面 17 页 / 120 次切换 / 273 个 Web 控件、首次配置 10 步 / 3 布局均通过。滚动压力测试 68 场景通过，采集 3810 帧有效画面，背景不匹配采样为 0，输入保留；最大同步滚动调用耗时 3.03ms（该指标不是整帧延迟）。自定义深色背景未触发大面积闪白断言。GDI 资源计数从 48 增至 109，包含各页面和尺寸的缓存，不能据此宣称长期运行无泄漏。
