# 首次配置渲染与交互路线评估 · 2026-10-20

用户报告首次配置窗口放大时严重屏闪，背景杂乱，并询问能否更好地将原网页流程融入软件。本轮是现场检查、视频参考分析与路线评估，没有将配置流程替换为新架构，也没有宣称闪烁已修复。

## 检查结果和验收缺口

- 本轮用 FFmpeg/FFprobe 读取用户提供的两段 MP4，分别长 116.171 秒、165.267 秒；按时间抽帧覆盖全片，并加密查看首段开头。它们主要讲提示、确认、抽屉和反馈组件的交互分工，不是要求应用某种视频配色。
- 当前首次配置仍为 `SetupWizard` WinForms 窗口。`BuildPage` 给普通 Panel 设置整页 `BackgroundImage` 并使用 `ImageLayout.Stretch`；前景标题、说明、卡片和按钮各自定位，页面缩放使用独立 sx/sy。
- `WizardTitle` 是透明、自绘、定时失效的子控件；标题重绘与原生兄弟控件重绘叠在大面积拉伸位图之上。窗体本身开双缓冲，不等于所有子控件合成为同一画面。这是需要做帧采样验证的绘制风险，不能仅凭源码断言所有屏闪已定位。
- 实际打开独立预览并最大化，看到素材被拉伸、常规尺寸下回顾页的图片与结果区域重叠、大窗口下图文大小不协调。系统动画完成后的单帧只能证明静态画面，不足以量化闪烁。
- 上轮 `--layouttest` 和 `--scrolltest` 对象是 `MainForm`；`--welcometest` 检查首次配置逻辑与几个固定尺寸，没有进行首次配置交互缩放的连续屏幕帧采样。因此“工作台滚动通过”不能推出“首次配置放大无闪烁”。

原视频、抽帧和可能包含用户桌宠的现场截图只保存在本机 `acceptance/video-reference-20261020/`，不加入仓库或发行物。

## 推荐路线：只将首次配置迁移为内嵌 WebView2

原网页设计保留为 HTML/CSS/JS，嵌入现有 Windows 程序中的专用配置窗口。配置仍独立于工作台、一步一个页面；不是打开外部浏览器，也不需要启动 TTS 后才能显示。

模块边界：

1. Web 页面：布局、动画、说明、输入和任务状态显示。
2. C# 宿主：文件选择器、消息校验、任务调度、取消、退出与本机资源访问。
3. 现有 `SetupWorkflow` / 模块安装工具 / 服务接口：真正的安装、保存、试听、Harness 和 AIRI 验证。
4. WebView2 运行时：作为可检测和补齐的独立 UI 依赖；联网引导安装及离线补齐包都要覆盖，缺失时仍提供原生安装/稍后配置入口。

采用本地虚拟域名映射加载随程序携带的前端文件；不依赖旧的 51270 预览服务器，也不加载在线 CDN。前后端使用结构化消息、操作白名单和请求 ID；页面卸载或用户取消后，不允许过期任务更新新步骤。

旧网页 `docs/design-review/20261019-black-white-stage/` 仍含 `reviewBridge`、示意数据与定时演示。可以复用视觉代码，但不能直接把演示进度、绿色状态或成功动画当作真实安装与验证。必须把每个按钮接回真实后端，再做从全新目录开始的验收。

官方依据：

- [WinForms 中的 WebView2 与双向消息](https://learn.microsoft.com/microsoft-edge/webview2/get-started/winforms)
- [本地内容与虚拟主机映射](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/working-with-local-content)
- [Evergreen / Fixed Version 部署方式](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/evergreen-vs-fixed-version)

这条路线有望更好地保留网页的布局和动画，但不是自动消除所有卡顿的保证；还需对页面生命周期、图片解码、GPU 竞争、最大化及缩放实测。

## 其他路线

| 路线 | 本项目取舍 |
| --- | --- |
| 继续修原生 WinForms | 可以先做合成绘制、背景缓存、缩放时暂停动效、等比素材和布局整理；适合短期止血，但保留网页设计需要大量手工复刻 |
| WebView2 + 现有后端 | 首选；只替换配置表现层，范围可控，保留已有安装与验证模块 |
| WPF / WinUI 重新实现 | 能做原生现代界面，但现有控件、布局和动画要重新实现，迁移范围更大 |
| Electron / Tauri 整体壳 | 可以承载网页，但将引入新的桌面宿主、发布与生命周期维护，当前没有必要为了配置模块整体换壳 |
| 外部浏览器配置 | 可作为调试或备用入口，但不符合当前希望配置融入软件窗口的目标 |

## 视觉处理建议

- 保留已经认可的 AIRI 素材和其独立构图；其他页面也保留各自的素材特色。
- 背景回到统一、低对比的石墨黑。3D 图片是可独立定位、等比显示的插画，不再铺满并拉伸整张图片；说明和结果区域有稳定留白。
- 不直接用遮罩或模糊层盖住重叠。标题、操作区和插画分别明确占位，窄窗口改排版，短窗口允许滚动。
- 标题先建立阅读焦点，插画为辅助；切页结束后只有当前页动画存活。减少动画立即切换，缩放时停止大范围过渡。

## 从视频选取的交互组件

| 组件 | 软件中的用途 | 行为 |
| --- | --- | --- |
| Tooltip / Popover | 按钮说明、轻量/完整包区别、引擎兼容说明 | 悬停或聚焦查看；关键缺项不能只藏在悬停提示中 |
| Inline Alert | 路径错误、台词缺失、环境缺项、接入验证失败 | 放在对应项目旁；显示原因、解决方法和重试入口，修复前不自行消失 |
| Drawer 侧边抽屉 | 声音参数、选择音色、连接详情、任务日志 | 保留当前页面上下文；有未保存内容时不直接点击遮罩丢弃 |
| Toast | 保存成功、复制完成、音色切换成功 | 轻量、不抢焦点；不承担重要错误信息 |
| Snackbar + 撤销 | 归档声音方案、移除列表项 | 有可恢复语义才提供撤销；不伪装成删除物理模型文件的撤销 |
| Modal / AlertDialog | 无法恢复的清空、覆盖、关闭仍在写入的安装任务 | 仅在必须作决定时阻断；按钮明确写操作，不使用模糊“是/否” |
| Loading / 步骤状态 | 环境补齐、音色包导入导出、连接验证 | 展示真实任务阶段和结果；进度未知则显示不确定状态，不能造百分比 |

底部面板适合窄窗口的少量快捷操作；桌面宽屏优先侧边抽屉。自动朗读过程不弹普通成功 Toast；真实接入与播放验证通过后，才播放用户要求的成功庆祝动画。

## 迁移验收门槛

先做一个内嵌配置验证版本，再决定替换默认入口：

1. 普通、最大化、还原、快速拖动缩放和连续切页的真实屏幕帧采样；不能只看静态截图。
2. 多种窗口尺寸与目标 DPI，图片等比、图文不重叠、字号不被压小。
3. 全新电脑无 WebView2、联网/离线补齐、失败重试、稍后配置与回退原生入口。
4. 十步真实操作逐项接后端，验证安装状态、保存与跳过语义、取消、恢复；不使用示意成功代替回执。
5. 页面隐藏停止动画；缩放、后台、关闭时没有残留任务、计时器或重复音效。

本轮仅提交此评估与交接说明，程序二进制、用户配置和发行包不更换。
