# 模块化发布与清理

当前规则自 2026-10-22 的功能模块拆分起生效，替代历史“整套环境加 Fairy 默认声音”方案。

## 发布范围

软件本体不附带默认声音、参考录音、训练音色权重、声音归档、个人设置或可选音色包实现。四类安装包分别制作：本体 ZIP、`.ttsengine` 引擎包、`.ttsenvironment` 环境包、`.avmodule` 功能扩展。音色归档不是安装本体的必要模块，也不出现在首次配置中。

本体包含 UI、核心语音服务、连接器、原生模块安装器和说明。TTS 基础模型应确认来源及许可，不要把训练角色模型当成通用基础模型随引擎包默认附带。模块本身只带实现，不带录音或模型。具体音色的使用、训练及传播授权仍需独立确认。

## 构建与归档

在新的空目录构建本体，执行当前 Python、Node 和 GUI 验收；尤其验证缺少可选源码的独立 Python 进程仍能保存本地声音方案。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -OutputDirectory D:/AgentBuild
python tools/module_packages.py application --root D:/AgentBuild --output D:/Releases/Agent本体.zip
```

引擎和环境分别使用同一工具的 `engine`、`environment` 子命令。功能模块按自己的构建脚本独立生成；音色包模块的脚本在 `optional-modules/voice-packages/build.ps1`。根构建不编译或复制该目录。发布文件必须是新文件，不能覆盖旧包冒充新验收。

旧 `tools/package_portable.py stage` 已停用，会明确失败，不再把 Fairy 模型和录音加入暂存。兼容 `archive` 入口仅归档无声音的本体，仍要求明确的发布确认参数。本轮只制作可选功能模块，没有制作整套发布包。

## 交付检查

1. 本体清单没有 `modules/`、用户 `data/`、`voices/`、`voice-model-packages/`、默认音色清单或旧归档脚本。
2. 空白安装首次进入配置，没有默认声音；主动跳过可进入控制台。旧 `bundled-voice.json` 即使残留，也不能注入声音或账号设置。
3. 手动准备模型与参考录音后，核心 TTS、声音设置、声音方案及连接不依赖音色包模块。
4. 单独安装模块，验证打开、真实导出导入、兼容拒绝、重复复用和移除；移除后核心真实生成仍可用。
5. 在干净目标电脑复验环境安装与实际播放。构建成功或绿色页面不能代替硬件和账号验证。
6. 各类包分别附版本、哈希、许可及来源；声音资产另核对授权。GitHub 不提交声音、环境、密钥和本机测试材料。

## 清理边界

更新已有安装时，把退役的四个音色包／旧配置归档脚本、相应 Python 缓存及默认音色清单移到安装目录外的版本备份，防止旧代码继续可调用。不要删除用户模型、参考录音、声音方案或用户自己保存的音色包。恢复副本不进入发行清单。

任何递归清理先核对绝对路径及链接目标；不要按 `.pth` 等扩展名批量删除。保留 Git 历史、当前设置、唯一训练素材、验收证据和必要回退副本。另见《模块安装与配置指南》及《功能模块架构与验收》。
