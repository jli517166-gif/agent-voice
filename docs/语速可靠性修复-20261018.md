# 语速热更新与可靠性验收 · 2026-10-18

## 已确认原因

旧实现把整个 `voice` 对象作为模型加载身份。用户只修改语速时，服务也会停止当前任务和队列、关闭 TTS 工作进程并重新加载模型。连续调整因此产生取消、切换等待和超时，并被用户观察为失败率突然升高。

CosyVoice 还存在一个独立的边界错误：界面的 `0.70` 经二进制浮点运算后可能变成 `-30.000000000000004%`，超过工作进程允许的 `-30%` 下限，因此最低语速会被直接拒绝。

## 修复后的行为

- 语速、音量和资产标记作为运行参数，不参与模型加载身份，也不清除 Harness／AIRI 已完成的真实连接验证。
- 每项任务在入队时保存自己的完整声音快照。调整前已提交的任务继续使用旧语速，之后提交的任务使用新语速；当前任务和队列不会被取消。
- 只有引擎、版本、模型目录、参考录音、逐字台词及实际影响工作进程的高级声音参数变化时才重载模型。
- CosyVoice 的速度百分比在发送给工作进程前舍入并限制到 `[-30, 30]`，确保 `0.70` 与 `1.30` 两个合法边界不会因浮点误差失败。

## 真实验收

正式安装 `E:\App\Agent 测试` 已同步修复。先对 CosyVoice、GPT-SoVITS v5 Turbo、GPT-SoVITS ProPlus 分别生成 `0.70、0.85、1.00、1.15、1.30` 五档语速，共 15 项，全部完成。

随后每个引擎运行四轮五档循环，共 60 项真实 GPU 合成：完成 60，失败 0，观测成功率 100%。每次速度保存后均检查服务保持 `ready` 且 `switching=false`。原始报告位于正式安装的 `data/acceptance/speed-hot-update-20261018.json` 与 `data/acceptance/speed-stress-20261018.json`，其中不含发布资产。

这次结果证明当前机器、当前三种引擎和规定语速范围通过，不表示任意硬件、模型、录音或未来上游版本永久保证 100%。产品验收门槛仍为至少 95%，目标电脑应运行自己的换机语音链路验收。

## 换机边界

目标电脑仅联网不会自动授予远程控制，也不会自动完成验收。它必须运行已经授权的远程执行端，或者由用户在目标电脑启动程序并执行“补齐环境”和“换机语音链路验收”。Harness 与 AIRI 还要在目标电脑使用各自的真实挑战和播放回执验证。
