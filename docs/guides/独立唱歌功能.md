# 独立唱歌功能

Agent 唱歌与 Agent Voice 的 TTS 分开运行。TTS 负责把 Harness 正文读出来；唱歌软件负责歌词、音乐风格、歌曲任务和歌曲文件。两者不会共用模型目录，也不会把唱歌模型写进声音方案。

## 安装与目录

1. 在“模块”页导入 `Agent唱歌-*.avmodule`。
2. 再导入受支持的 `*.singengine`，目前实测适配 ACE-Step 1.5。
3. 唱歌软件位于 `modules/agent-singing/module.exe`，引擎位于 `singing-engines/<引擎 id>`。
4. 生成任务和默认输出位于 `data/singing`；可在唱歌工作台中把歌曲保存位置改到其他目录。

软件本体、唱歌工作台和唱歌引擎分别打包。不安装唱歌模块不会影响朗读、Harness、AIRI 或 TTS。

## 使用

从 Agent Voice 左侧点击“唱歌”，选择已安装引擎，填写风格与歌词，再提交生成。任务在后台运行，工作台会显示完成或失败以及输出位置。首次启动 ACE-Step 通常需要加载模型，耗时明显长于后续任务。

DeepSeek Harness 安装最新版 MCP 后，聊天栏“语音”菜单提供“打开唱歌”；语言命令还可列出／切换唱歌引擎、提交歌词、查询任务和修改输出目录。提交成功只表示进入歌曲队列，不表示已经生成完成。

## DeepSeek 桌宠语音

原版 `PC2005-cloud/dsh-pet`：连接器使用其公开的 `petApi7340.voice.register` 扩展接口，把 Agent Voice 当前声音注册为桌宠的外部语音提供方。需要同时满足：DeepSeek Harness 已重载连接器、dsh-pet 宿主插件已启用、Agent Voice 服务已启动、当前 TTS 能在桌宠规定的 15 秒内生成。当前电脑安装的 `MerZlin/dsh-pet-indesktop` 属于独立程序，不提供该宿主插件接口；原版注册功能不会自动接到独立版。

反向使用时，在 Agent Voice 的“声音设置”中选择 `dsh-pet · 当前音色`，再选连接方式：

- **独立桌宠**：适配 `MerZlin/dsh-pet-indesktop` 的 Chat 版，读取当前 Windows 用户 `%APPDATA%/dsh-pet-standalone-webm-chat/config.json` 中的 Edge 音色、语速和音调。需要安装可选的 `edge-tts` 依赖并联网生成；**待朗读文字会发送到 Edge 在线语音服务**。切换桌宠设置后下一句会使用新设置。当前只适配该独立版的 Edge 后端，若桌宠改用 SAPI、豆包或 Mimo，会明确提示尚未适配。
- **宿主插件**：适配原项目 `PC2005-cloud/dsh-pet`。填写本机 Web 地址 `http://127.0.0.1:<端口>/dsh-pet-7340`；实际端口以 DSH Web 服务显示的地址为准。音色 ID 可留空，或填写 `/voice/voices` 返回的 ID。此模式通过 `/voice/speak` 获取 MP3。

两种方式都会由 Agent Voice 的 FFmpeg 把 MP3 转入现有 WAV 朗读队列，不需要本地克隆权重或参考录音。独立版不能使用宿主插件的 HTTP 地址；宿主插件也不会自动读取独立版设置。

原版宿主插件的两个方向不能互相调用：选用 dsh-pet 引擎时，连接器会停用“Agent Voice 当前声音”的桌宠注册；切回本地 TTS 后再恢复注册。独立版目前仅实现“桌宠 Edge 设置 → Agent Voice”，要让独立桌宠本身使用 Agent Voice，需要按其 provider 源码接口适配并重建桌宠；现有独立版安装包不提供运行时 provider 装载能力。如果插件版本不提供上述原版接口，程序会显示连接或音色列表错误，不会假装成功。

### 独立桌宠使用 Agent Voice 声音（源码适配）

`dsh-pet-indesktop` 官方提供 TTS provider 扩展点，但已打包的 exe 不会动态装载新 Python provider。源码适配在本项目的 `integrations/dsh-pet-indesktop/agent_voice.py`，安装脚本仅修改**你另行取得的桌宠源码副本**，不会覆盖当前桌宠程序、用户设置或素材。在 Agent Voice 源码目录执行：

```powershell
$petSource = 'D:\path\to\dsh-pet-indesktop'
git clone https://github.com/MerZlin/dsh-pet-indesktop.git $petSource
python -X utf8 .\tools\prepare_pet_source.py --pet-source $petSource
```

脚本会检查上游的 provider 注册表与缓存调用点是否仍与实测版本匹配，全部匹配后写入 provider，并在原文件旁保留 `.agent-voice.bak`。然后按[桌宠上游构建说明](https://github.com/MerZlin/dsh-pet-indesktop/blob/main/docs/ONEDIR_PACKAGING.md)重新构建独立桌宠。在新桌宠的“语音”设置中选择 `Agent Voice（本机当前声音）`，填写 `agent语音.exe` 所在目录，开启助手回复朗读并试听。`current` 跟随 Agent Voice 当前声音；也可填写一个已保存声音方案的 ID。该 provider 只连接 `127.0.0.1`，从本机 Agent Voice 设置读取令牌；它不缓存音频，切换声音后下一句会重新合成。选择 Agent Voice 桌宠声音时，Agent Voice 自身不要再选择桌宠声音，以免循环。**尚未完成新桌宠 exe 的构建与实际桌宠播放验收时，不应视为双向接入成功。**

构建前检查 `PATH` 中是否混入其他软件自带的 Poppler `Library/bin`。实测 PyInstaller 曾把其中的 `icuuc.dll` 误收进桌宠包，覆盖 Qt 需要的系统 ICU；结果是 `QtCore` 报“找不到指定的程序”。从本次构建进程的 `PATH` 排除该目录后，Qt DLL 加载检查通过。仅改环境变量或当前构建产物，不要删除其他软件安装的 DLL。离屏模式 `QT_QPA_PLATFORM=offscreen` 不会生成构建脚本需要检测的普通窗口句柄；正式窗口冒烟应使用正常桌面会话。

该兼容层不复制 dsh-pet 的角色、动画、声音或其他素材。桌宠更新改变接口时，应重新安装连接器并复验；失败会明确报错，不会静默回退到另一种声音。

## 许可与内容

只使用你有权处理的歌词、旋律、录音、角色声音和模型。ACE-Step 源码许可不自动覆盖模型权重、训练数据、歌曲版权、表演权、声音人格或生成内容的发布用途。发布歌曲前应按实际来源和用途分别核对。
