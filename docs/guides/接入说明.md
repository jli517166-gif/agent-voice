# Harness 与 AIRI 接入

## Harness

内置适配范围为 Codex、DeepSeek Harness。其他宿主需要单独实现连接器，不能仅凭选中目录就视为支持。

1. 在连接页面选择目标宿主的安装或配置目录。
2. 使用该版本提供的安装入口准备连接器和 MCP 控制。
3. 重载插件或重启宿主，确认服务器已启用。
4. 执行检查，区分配置存在、协议通过与客户端实际读取工具三个阶段。
5. 需要自动朗读时另行开启，并选择可读取的项目或会话范围。

MCP 自检核对路径、启用状态、initialize、工具列表和只读状态调用。独立探针通过不等于宿主已经重载；应同时核对当前宿主的工具读取回执。自动朗读的事件投递和实际播放是另外的检查，不应由一次文件安装推定。

Codex 使用原生技能入口与 MCP 语言命令，不提供聊天栏常驻自定义按钮，也不接管客户端内置朗读。DeepSeek 适配器可提供聊天输入区控制入口；宿主升级后应重新检查兼容性。

MCP 1.5.1 的“关闭服务”会等待实际退出后再返回成功；15 秒内无法确认停止则明确报错。升级程序后，请重载宿主的 MCP 连接，使已启动的旧服务进程载入新代码。

## AIRI

AIRI 联动默认关闭，本机播放不依赖它。启用时选择已经安装并登录的 AIRI 目录，不复制第二个实例。桥接让 AIRI 请求本地语音并接收播放任务，成功判定需包含实际播放和嘴型回执。

原应用应保留可恢复备份。AIRI 更新可能覆盖桥接，更新后重新执行连接检查。退出或关闭联动后，不应继续占用过期任务。

## 搬迁与错误

搬迁后核对 MCP command、args、root、cwd 是否指向当前程序。修复后重载宿主；不要把失效路径、旧进程回执或单纯心跳当作当前连接。

详细协议见 [MCP 开发说明](MCP控制插件开发说明.md)和 [Harness 开发指南](Harness二次开发指南.md)。
